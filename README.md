# 泰拉档案馆 · 人物与剧情

SillyTavern 独立前端扩展，版本 **0.2.0 预览版**。适配电脑、手机及平板；不需要额外的服务器插件、Python 或摘要 API。

以 PRTS 干员图鉴卡片为人物入口，点击即可读取档案、查看立绘，并按需向当前聊天提供参考。剧情按分类、大章节/活动/人物、具体剧情逐层浏览，支持分段阅读、简单选项和手动确认进度，**不包含动画播放器**。

## 0.2.0 预览版更新

- 人物首页自动读取 Wiki 干员一览：职业和星级筛选，实装/名称/稀有度六种排序，半身像/头像/列表切换及分页。
- 人物详情采用左侧立绘与缩略图、右侧档案页签布局，支持基础档案、综合体检、客观履历、档案资料、语音和模组。
- 剧情改为五类卡片：首页 → 分类 → 大章节/活动/干员 → 具体剧情。不再将所有关卡堆在一个列表。
- 常驻插曲根据 PRTS 托管的游戏 `retro_table.json` 元数据识别，不手写猜测名单。尚未常驻的活动可能仍在活动分类；分类源不可用会明确提示。
- 剧情分类的图片为氛围背景，不冒充每篇活动的官方封面；图示中的虚构人物、章名和收录率不会被当作真实数据。
- 兼容原有浏览器缓存和当前聊天的资料选择，不需要清空旧资料。

**这是提前提供的可上传预览版本，不是最终稳定版。** 已验证真实目录：434 位干员、18 个主线分组、79 个活动分组、7 个常驻插曲分组、12 个其他分组，以及 334 个有密录的人物分组（数字随站点更新变化）。本轮完整的电脑/手机界面回归尚未全部完成。

### 上传 GitHub

将此文件夹内的所有文件和文件夹上传到仓库根目录，使首页直接出现 `manifest.json`、`index.js`、`directory.js`、`views.js`、`gallery.css` 等文件，不能再套一层文件夹。不要上传 `node_modules`。

本扩展直接使用源码 ES Modules，不需要 `dist` 或构建步骤。发布代码不等于获得游戏文本和图片的转载授权；本仓库不内置完整游戏资料或美术素材。

## 安装到你的本机酒馆

本次制作没有覆盖本机现有扩展、角色卡或聊天数据。安装前仍建议按日常习惯备份酒馆数据。

1. 解压安装包，得到 `terra-archive` 文件夹。
2. 将整个文件夹放到：

   ```text
   C:\Users\Administrator\Downloads\SillyTavern-release\SillyTavern-release\data\default-user\extensions\terra-archive
   ```

3. 文件夹内应直接有 `manifest.json`、`index.js`、`core.js`、`wiki.js`、`storage.js`、`style.css`、`directory.js`、`views.js`、`gallery.css`，不能多套一层。
4. 重新打开酒馆页面，电脑按 **Ctrl+F5**；手机刷新。若尚未识别扩展，重启酒馆后再次刷新。
5. 页面右下方会出现 **◇ 泰拉档案馆** 按钮，点击打开。手机上如果按钮被挡住或看不到，可以：
   - 按住按钮拖到任意位置（位置会记住）；
   - 或点酒馆输入框左侧的 **扩展菜单（魔杖图标）→ 泰拉档案馆** 打开；
   - 在 **设置 → 显示与按钮** 中恢复按钮默认位置，或调整人物立绘缩放、高度、垂直位置以及图鉴卡片大小（只保存在当前设备）。

如之前安装了同名测试版本，先备份其目录。不要同时安装多个不同名字的副本。

手机通过你原有的方式访问同一酒馆即可。首次加载资料需要手机能联网访问 PRTS；不需要手机单独安装扩展文件。建议使用近期 Chrome、Edge、Firefox 或 Safari。

## 人物资料

1. 打开人物页，插件自动读取 Wiki 图鉴目录。通过职业、星级、排序和关键字筛选，再点击人物卡片。
2. 左侧切换立绘，右侧通过页签查看不同档案；“备用入口”仍可直接输入名字或链接。
3. 点击 **加入当前聊天** 后，可勾选需要的档案条目。
4. 默认仅勾选基础档案、客观履历。高信赖档案、模组与语音需要主动勾选。
5. 立绘区可查看原图。点击 **缓存此图**，图片会存进当前浏览器，以后可在本机离线查看。

人物载入和加入聊天是两回事：仅查看不会自动注入。可同时启用最多 12 位人物。初雪和圣聆初雪按不同页面分开保存，不会自动合并其时期与身份。

档案是引用资料，模型仍可能解释错误，不能据此保证输出逐字忠于原作。条目勾选不是自动剧情防剧透系统，基础履历本身也可能揭示后续发展，请自行核对。

## 剧情

1. 在剧情页选择分类卡片，再选择大章节、活动或干员，最后点击具体“行动前 / 行动后”等剧情入口；也可在备用入口粘贴具体链接。
2. 例如：`https://prts.wiki/w/0-7_感染/BEG`。
3. 若粘贴的是活动或章节总页，而不是具体剧情页，请返回分类网格选择对应篇章。
4. 阅读时点击 **确认至此**，当前聊天才会得到该位置之前最近的剧情片段。翻页本身不推进聊天进度。
5. 选项需要你主动确认。切换选项会清除其后选项与进度，以免混合互斥分支。

第一版支持常见顺序脚本及简单 `Decision / Predicate` 结构。遇到复杂跳转、无法确认的条件、嵌套分支会暂停解析，提示到原页面核对。**不是完整游戏脚本执行器，不会自动跟随 AI 对话推进剧情，也不会猜造节点。**

背景、立绘等演出指令不播放。保留场景资源编号作为场景标记，但不会将这些美术资源编号当成人物姓名。部分新格式或特殊字幕仍可能无法完整识别，请以原页为准。

## 如何注入酒馆

- 使用酒馆的独立扩展提示槽 `terra_archive_reference`。
- 仅包含当前聊天启用的人物条目、已确认剧情进度之前最近的片段。
- 总上限默认 12,000 字符，可在设置中调整到 1,000–30,000 字符。**字符数不是 token 数**。
- 当前剧情片段优先，人物按加入顺序排列；超过上限会明确标记截断。
- 关闭设置中的参考注入开关，会立即清除此扩展的提示槽。
- 切换聊天不会继承上个聊天的启用资料。
- 没有本机缓存的已关联资料不会被自动编造或偷偷联网加载，请在资料库点 **补载本机缺失资料**。
- 不会调用模型 API 来生成档案，不会替换角色卡，不会写入正文，不会改动柏宝书数据。

## 数据保存与跨设备

| 内容 | 位置 |
| --- | --- |
| 人物、剧情文本、图片索引、主动缓存的图片 | 当前设备、当前浏览器的 IndexedDB |
| 注入总开关、字符上限 | 酒馆用户的扩展设置 |
| 当前聊天人物选择、勾选条目、剧情进度和选项 | 酒馆聊天 metadata |

手机与电脑不会自动共享浏览器缓存。可在资料库 **导出文本与图片索引**，在另一设备导入；或在另一设备补载当前聊天已关联的资料。

JSON 导出 **不包含图片二进制，也不包含聊天关联配置**。导入会清除当前聊天的本扩展关联，避免档案版本或进度错位，需要重新启用。其他聊天不会被清空；如替换了它们关联的缓存，请重新核对其条目与剧情进度。

请勿清除浏览器站点数据，否则本机缓存会丢失。删除插件目录不会自动删除浏览器缓存或聊天 metadata。

## 本版边界

- 主要适配有“干员档案”结构的已实装干员；不宣称为所有未实装 NPC 生成完整人设。
- 图片目前是人物页立绘、精英化立绘与时装，不是全套剧情表情差分；图片也不会自动作为视觉输入发送给模型。
- 不自动为整章所有出场角色批量采集档案。
- 语音补充可能含多语言；过长条目会标明截断。
- PRTS 页面结构、接口或跨域策略变化时，需要更新适配器。网络错误会显示在面板底部；已有文本缓存仍可使用。

## 来源与版权

采用 PRTS 的公开 MediaWiki API（显式 `origin=*`），请求固定域名，单并发并限速，不携带酒馆凭据，不绕过访问限制。

本插件 **不内置游戏原文、美术素材或全站镜像**。资料由用户主动选择后读取，并保留来源链接和更新时间。游戏文字和美术素材的版权属于相应权利人；请遵守站点规则，不要未经许可公开打包或分发采集内容。代码公开与游戏内容授权是两回事。

## 开发与验证

扩展本体使用原生 ES Modules，无须构建。`node_modules` 只用于开发测试，安装包不包含它。

```text
npm install
npm test
npm run check
node tests/live-smoke.mjs
node tests/dev-server.mjs
```

预览地址：`http://127.0.0.1:18746/tests/preview.html`。预览是独立模拟宿主，不是实际酒馆；测试夹具为自创占位内容。`live-smoke` 仅验证公开接口结构，不将原文落盘或打包。

0.1.0 曾通过 32 项测试及桌面/手机布局验证。0.2.0 新增图鉴与分层目录测试，并提供 `node tests/directory-live.mjs` 验证真实接口。本次提前打包的预览版尚未完成所有新版界面回归；不能将上一版的布局验证视为新版已全部验证。

未在你的真实聊天中发起模型请求。复杂章节和不同手机浏览器仍需要后续试用反馈。
